## 2. 고친 것

### 2.1 매도청구권 — 옵션차익혼합할인법을 더했다

**문제.** 격자 안에서 `MIN(계속보유, 콜금액)` 으로 처리하고 있었다. 이건
**회사가 직접 되사가는** 발행자 콜옵션 방식이다. 그런데 티사이언티픽 공시는
*"발행회사 **및 발행회사가 지정하는 자**"* — 제3자 지정 가능 콜옵션이다.

책이 둘을 명확히 가른다 (4.2~4.3).

| | 성격 | 계산 |
|---|---|---|
| 발행자 콜옵션 | 채권 부분. 조기상환 페이오프 | 격자 안에서 처리 |
| **제3자 지정 가능 콜옵션** | **복합옵션** (a call on a convertible bond) | 전환사채를 기초자산으로 별도 평가 |

> 제3자 지정 가능 콜옵션은 … 그 기초자산이 전환사채인 '옵션에 대한 옵션(an
> option on an option)'의 특성을 반영하는 **'복합옵션(compound option)' 평가
> 모형이 적용되어야 한다** — 사례 1105 해설1

책이 드는 세 방법 (4.1.1)

| 방법 | 책의 평가 |
|---|---|
| 상품자체기초자산적용법 | 전환사채 변동성 관측이 어려워 부적절 |
| 유무가치비교법 | 종전 앱이 쓰던 것 |
| **옵션차익혼합할인법** | *"실무적으로 많이 채택"*, 책이 이 기준으로 설명 |

> 유무가치비교법과 옵션차익혼합할인법은 개념적으로 그 결과가 동일하여야 하나
> 세부적인 구현방법에서 시장에서의 실무가 다양하게 진행되고 있어 그 차이가
> 종종 발생하는 것으로 보여진다.

**넣은 것.** `call_third_party()` 를 새로 만들고 `Terms.k_method` 로 고르게 했다.
기본값 0(유무가치비교법)이라 **기존 결과와 예전 시나리오 JSON 이 그대로 유지된다.**

새 격자를 만들지 않는다. `engine()` 이 노드마다 `E · B · V · P` 를 담아 돌려주므로
그 `memo` 를 한 번 더 역진하면 된다. 자식 노드 키(`up` · `dn`)를 노드에 남기게 해
리픽싱 경로를 다시 계산할 필요도 없앴다.

**기초자산 정의에 주의한다.**

> 콜옵션의 기초자산은 **콜과 그 부속조항**(콜행사기간동안 투자자에게 부가된
> **채권보유의무** 등)**을 포함하지 않은** 전환사채이다 — 4.4.2 · 4.4.3

`decompose()` 의 `full = engine(tm, call=False)` 이 정확히 이것이다 — 콜도 없고
`k_lock`(의무보유)도 걸리지 않는다. 부속예제 4-4의 기초자산 트리도
`Flag(Conversion)` 에 콜 조건이 없고 `Flag(Call)=0` 인 것을 확인했다.

반대로 유무가치비교법에서는 의무보유가 콜 값에 포함되는 것이 맞다 (4.5.2 는
부속조항을 빼라고 하지 않는다). 두 방법을 나란히 둘 때 이 차이를 지켜야 한다.

없다"* 고 인정한다.

### 2.2 전환권이 부채일 때 배분이 틀렸다

`allocate()` 의 `liability` 갈래가 이랬다.

```python
deriv = b2 - b0 - ca          # ← "- ca" 가 잘못
host_acc = 100 - deriv + ca
```

매도청구권은 제3자 지정이 가능해 기준서 1109 문단 4.3.1 상 **별도의 금융상품**
이다. 복합내재파생상품에 들어가지 않으므로 거기서 빼면 안 된다. 사례 1105
해설2대로 발행가액을 배분하면 **전환사채에 배분된 금액은 100 + ca** 다.

**합칠 것을 합치는 것 자체는 이미 맞았다.**

> 전환권 및 풋옵션(또는 콜옵션)은 서로 독립적이지 아니하므로 하나의
> 복합내재파생상품으로 처리하여야 하며 … **'전체로서(as a whole)'** 주계약과
> 분리하여 … 파생상품부채라는 **하나의 회계단위**로 인식 및 측정하고 표시하는
> 것이 적절하다 — 책 p51, 기준서 1109 문단 B4.3.4

| 티사이언티픽 · 전환권 부채 | 종전 | 고친 뒤 |
|---|---|---|
| 주계약 (잔여) | 44.4977 | **30.9804** |
| 복합내재파생상품 · 파생상품부채 | 69.0196 | **82.5369** |
| 매도청구권 · 파생상품자산 | −13.5173 | −13.5173 |
| 합계 | 100.0000 | 100.0000 |

**13.5173 씩** 어긋나 있었다.

조서의 **분개표와 수식 조서에도 같은 옛 산식이 남아 있었다.** 배분표는 `allocate()` 를
쓰는데 분개표는 따로 계산해 같은 시트 안에서 두 표가 달랐다. 분개를 배분표에서 뒤집어
만들도록 바꿔 다시 갈라질 수 없게 했다. 수식 조서의 결과 시트도 `C6−C13−C16` 에서
`C6−C13` 으로 고쳤다.

`equity` 갈래는 그대로 뒀다. 전환권이 자본이면 남는 내재파생이 조기상환권
하나뿐이라 합칠 대상이 없고, 계산이 1032 문단 31·32 및 사례 1108과 맞는다.

### 2.3 BDT 적용 필요여부 판정을 검산 탭에 넣었다

BDT 모형 자체는 만들지 않는다. **써야 하는지 판단할 재료**만 보여준다.

## 3. 뒤이어 반영한 것

> **갱신** — 3.1 과 3.2 는 이후 반영했다. 아래는 그 배경과 근거다.

### 3.1 현물이자율 입력의 복리 관행

책 3.7.4.4가 **오류 사례**로 명시한다.

> 회사채 제로커브 생성시 분기복리 기준의 현물이자율을 생성한 후, 할인계수나
> 위험중립확률 산출 시 연속복리 기준으로 계산하는 것은 오류이다

`spot_from_zero()` 는 `math.log(1+r)` 로 **연복리를 가정해 고정**한다. 사례 1130의
zero rate 가 연복리이므로 그 출처에는 맞지만, 분기복리 곡선을 받으면 틀린다.

| 5년 현물 19.05% | 연속환산 | DF | 주계약 |
|---|---|---|---|
| 연복리 (현재) | 17.4373% | 0.41817 | 41.82 |
| 분기복리 | 18.6103% | 0.39435 | 39.44 |

**반영했다.** `spot_from_zero(pts, m)` 가 `m·ln(1 + r/m)` 로 환산하고, `curves()` 가
`cmp_rf` · `cmp_cr` 를 넘긴다. `m=1` 이면 종전 `ln(1+r)` 로 되돌아와 기존 결과가 바뀌지
않는다. 사이드바에 `입력 유형` 선택기를 만들어 `spot` 모드를 화면에서 쓸 수 있게 했고,
고를 때 이표 횟수를 복리 횟수로 맞추라는 안내를 띄운다. 조서 가정 시트에도 복리 횟수를
함께 적는다.

### 3.2 조기상환권 밀접관련성 판단

사례 1105 해설3이 판단 논리를 준다.

> 주계약의 상각후원가는 전환사채에 배분된 거래가격인 CU1,200을 기준으로
> 산출되나, 풋옵션 행사금액은 액면금액인 CU1,000을 기준으로 산출되므로 … 거의
> 같지 않을 것이다. 따라서 풋옵션은 주계약과 분리하여 회계처리하는 것이 적절하다

**반영했다.** 검산 탭에 첫 조기상환일의 행사금액과 같은 시점 주계약 상각후원가를
나란히 띄우고 차이가 10%를 넘으면 분리, 아니면 문단 B4.3.5(5)(가) 예외 가능성을
알린다. 배분 자체는 여전히 분리를 전제하므로, 예외에 해당하면 회계처리 탭 값을 그대로
쓰기 전에 판단을 확인하라는 문구를 함께 띄운다.

티사이언티픽은 행사금액 100.00 대 상각후원가 55.52 로 **80.1%** 차이가 나 분리가 맞다.

## 3.3 전면 재검토에서 찾은 것

**만기 이자가 빠져 있었다.** 표면이자가 있는 사채에서 만기 노드가 이자를 더하지 않고
상환금액만 잡았다. 책 5-7 의 만기 현금흐름은 액면이자 50 + 원금 10,000 + 상환할증금
1,653.14 다. 표면 3%/보장 7% 로 시험하니 주계약이 55.9719 로, 확정현금흐름 현가
56.2533 보다 0.2814 낮았다. 만기 노드의 현금 갈래에 이자를 더했고 수식 조서의 만기
열도 시트 성격에 맞춰 맞췄다. 표면이자율이 0 이면 값이 변하지 않는다.


경계 조건 14가지를 훑다 매도청구권 계산의 결함 둘을 찾았다.

**의무보유가 전환을 앞당기고 있었다.** 30% 트랜치의 전환 시작을 `k_lock` 으로 **덮어쓰고**
있었다. 의무보유는 전환을 **늦추기만** 해야 하는데, `k_lock` 이 전환 시작보다 이르면
오히려 30% 트랜치가 먼저 전환할 수 있게 됐다. 그러면 콜을 붙인 쪽이 더 비싸져
**매도청구권이 음수**가 된다. 전환 시작이 200개월인 계약으로 시험하니 −0.5449 가 나왔다.
`max(전환 시작, 의무보유)` 로 고쳤다. 수식 조서의 `30% 전환 시작` 스텝도 같이 맞췄다.

**매도청구 기간이 격자 밖인데 값이 남았다.** 행사 가능한 시점이 하나도 없으면
유무가치비교법의 차액에 **의무보유 효과만** 남아 1.2300 이 잡혔다. 옵션차익혼합할인법은
같은 조건에서 0 을 내 두 방법이 어긋났다. 행사 가능 시점이 없으면 매도청구권을 0 으로
둔다.

기본 설정의 값은 세 방법 모두 그대로다 (13.5173 / 8.9875 / 9.1899).

## 3.4 값 조서와 수식 조서를 맞췄다

수식 조서를 `formulas` 로 실제 계산해 엔진과 대조하니 **네 가지가 어긋나 있었다.**
그동안 수식 조서는 구조만 보고 숫자를 맞춰본 적이 없었다.

**할인에 한 스텝 뒤 이자율을 썼다.** 트리 수식이 `{다음 열}$11·$12·$16·$17` 을 참조했다.
열 i 의 11·12행은 구간 [i, i+1] 의 선도이자율이므로 i+1 에서 i 로 할인할 때는 **열 i** 를
써야 한다. 게다가 마지막 열에는 이자율이 비어 있어 **마지막 한 스텝이 아예 할인되지
않았다.** 주계약이 40.21 로, 옳은 값 37.52 보다 높게 나왔다. 27곳을 고쳤다.

**⑫ GS 할인율·⑱ 혼합할인율의 기준 시점.** 이 두 시트는 자식을 직전 시점으로 할인할 때
쓰이므로 **직전 구간**의 선도이자율을 써야 한다.

**조기상환·매도청구 행사금액이 옛 산식이었다.** 상환할증금을 고칠 때 엔진만 바꾸고
수식 조서를 놓쳤다. 표면 3%·보장 7%·반기·5년에서 조기상환금액이 141.06 대 123.46 으로
17.6 벌어졌다. 세 곳(트리 헤더 2행, ⑯ 부채요소)을 맞췄다.

**GS 전환확률의 판단 기준.** 엔진은 TF 판단(`kind`)으로 전환확률을 정하고 조서는 GS
자신의 판단으로 정했다. GS 모형이므로 GS 판단이 맞다. 엔진을 조서에 맞췄고, 책 4-2
재현이 128.1781 로 오히려 가까워졌다 (책 128.1790).

## 3.5 수식 조서가 신용위험 처리 선택을 무시했다

사이드바에서 **GS 를 골라도 수식 조서는 언제나 TF 값**을 실었다.
`build_xlsx_formula` 가 `tm.model` 을 한 번도 읽지 않았기 때문이다. 결과 시트의
70% 트랜치는 ⑧(TF)에서, 30% 트랜치는 ⑮(TF)에서 그대로 끌어왔고, GS 값 하나가
참고용으로 옆에 놓여 있을 뿐이었다.

티사이언티픽 조건에서 벌어진 폭이다.

| | 앱 화면 (GS) | 수식 조서 (TF 고정) | 차이 |
|---|---|---|---|
| 전환사채 전체 | 116.4037 | 120.0576 | 3.65 |
| 매도청구권 | 12.5044 | 13.5173 | 1.01 |
| 전환권대가 | 39.3208 | 40.3336 | 1.01 |

값 조서는 계산이 끝난 숫자를 받아 적으므로 옳았다. **같은 평가에서 두 조서가
다른 답을 내던 상태**였다.

고친 방법은 이렇다.

- **⑮ 30% 트랜치에 GS 를 붙였다.** ⑪~⑭ 와 같은 순서(전환확률 → 위험조정할인율 →
  보유가치 → 금융상품가치)를 30% 트랜치 자신의 헤더와 전환가치로 다시 놓았다.
  사·아·자·차 네 블록이다. 만기에서는 TF 와 GS 가 같으므로 그 열은 공유한다.
- **가정 시트에 `신용위험 처리 (0 TF / 1 GS)` 를 넣었다.** 전환권 분류·매도청구권
  평가방법과 같은 방식이다.
- **결과 시트 1번에 `적용 · 70% 트랜치` 와 `적용 · 30% 트랜치` 두 행을 두었다.**
  아래 구성요소는 모두 이 두 행만 본다.

주계약과 부채요소는 **전환이 없어 지분 몫이 0** 이므로 혼합할인율이 신용할인율과
같아져 TF 와 GS 가 항상 일치한다. 8개 조건에서 차이가 1e-14 이하임을 확인했다.
모형 선택이 갈라지는 곳은 트랜치 둘뿐이라 거기서 한 번만 고르면 된다.

**대조 범위도 넓혔다.** 전에는 결과 시트 9개 셀만 봤다. 이제 회계처리 시트의
배분표 각 줄과 분개 차·대변 합계까지 본다. 배분과 분개가 같은 시트 안에서
어긋났던 적이 있어 이 둘은 반드시 함께 봐야 한다. 시나리오도 10개로 늘려
TF·GS × 자본·부채 × 유무가치·옵션차익을 모두 지나가게 했다.

이제 **10 시나리오 × 13 항목**이 소수점까지 일치한다. 다시 어긋나지 않도록
`tests/조서대조.py` 로 자동화했다.

## 3.6 경제적 성질을 따로 확인했다

수치 대조와 별개로, 결과가 **반드시 만족해야 하는 성질**을 점검했다.

- **단조성** — 변동성↑·주가↑ 는 전환사채 가치를 올리고, 할인율↑ 은 내리며,
  매도청구 한도↑ 는 매도청구권 가치를 올린다. 모두 성립.
- **항등식** — 전환권대가 = 100 − 부채요소 + 매도청구권. 상각표의
  기초 + 이자 − 지급 = 만기상환금액. 표면이자 유무·지급주기와 무관하게 성립.
- **수렴** — 노드 간격을 월·2주·주로 바꾸면 전환사채 가치가 120.06 · 120.48 ·
  120.34 로 **폭 0.43(0.36%)** 안에서 움직인다. 격자 모형의 통상적인 진동이다.
  UI 는 이 세 간격만 제공한다. 더 성긴 간격(분기·6개월)에서는 계약상 조기상환
  12회·매도청구 5회·리픽싱 8회가 노드에 다 실리지 못해 회수 자체가 달라진다.
- **후속측정** — 평가기준일을 발행 후 0·6·12·24·36·54·59개월로 옮겨도 배분
  항등식과 유효이자율이 모두 정상이다. 24개월 뒤 매도청구권이 0 이 되는 것은
  매도청구 기간이 24개월에 끝나기 때문이고, 59개월에 전환권이 0 이 되는 것은
  전환 종료가 59개월이기 때문이다. 둘 다 계약 조건대로다.
- **극단 입력** — 변동성 5%~150%, 주가 전환가액의 1/10~10배, 표면 > 보장,
  전환기간 1노드, 옵션 전부 없음 등 12가지에서 발산·예외 없음.
- **시나리오 JSON** — 저장·복원 후 결과가 같고, `k_method` 가 없는 옛 파일도
  기본값 0 으로 읽힌다.
